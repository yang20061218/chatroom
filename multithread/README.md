# 多线程版本

这是聊天室项目的早期实现，采用一连接一线程模型。当前主版本已经迁移到仓库根目录的 epoll 单线程事件循环，本目录保留用于对照和回溯，不再作为主要开发位置。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `server.c` | 多线程服务端，每个客户端连接对应一个读线程 |
| `client.c` | 阻塞式客户端，使用登录、读取、写入和心跳线程 |
| `net.c` | TCP 监听、accept 和 connect 等网络基础函数 |
| `net.h` | 网络基础函数声明 |
| `protocol.c` | 11 字节协议头的打包、解包和阻塞收发 |
| `protocol.h` | 协议常量、命令字和函数声明 |
| `Makefile` | 多线程版本的构建规则 |
| `test_sticky.py` | 粘包和拆包测试脚本 |

## 编译

在本目录执行：

```bash
make
make WERROR=-Werror
```

## 运行

```bash
./server
./client
```

## 与根目录 epoll 版本的区别

- 本目录每个连接创建一个线程
- 根目录使用单线程 epoll 事件循环
- 本目录的读写函数是阻塞式实现
- 根目录使用非阻塞 fd、连接级读写缓冲区和 `EPOLLOUT`
- 两个版本使用相同的 11 字节应用层协议

## 限制

- 连接数增加时线程和栈内存开销明显
- 慢客户端可能长期占用对应线程
- 不再继续添加新功能，只用于历史对照
