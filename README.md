# Linux 多线程聊天室

用 C 写的 TCP 聊天室。服务端支持多客户端并发，客户端用昵称登录，发出的消息会实时广播给其他所有在线用户。

这是网络编程学习路线上的第一个项目，代码里保留了从"能跑"到"可靠"的每一步演进：从最开始的裸 socket 广播，到自定义应用层协议、解决粘包、加昵称和登录。

## 当前功能

- 多客户端并发，一连接一线程
- 昵称登录，允许中文，长度 1 到 31 字节，重名会被拒绝
- 按昵称广播消息，别人看到的是 `[小明] : 你好`
- 用户上线、下线提示
- 自定义二进制应用层协议，正确处理 TCP 粘包拆包
- 连接数上限保护，超出时拒绝新连接而不是崩溃

## 协议

11 字节定长头 + 变长 payload：

```
偏移   长度   字段      说明
0      4      magic     固定 "1218"
4      1      version   1
5      2      cmd       命令字，网络字节序
7      4      length    payload 字节数，网络字节序
11     -      payload   正文，最长 64 KB
```

命令字：

| 值 | 名称 | 说明 |
| --- | --- | --- |
| 1 | CMD_CHAT | 聊天消息 |
| 2 | CMD_EXIT | 主动退出 |
| 3 | CMD_HEART | 心跳（预留） |
| 4 | CMD_LOGIN | 登录请求，payload 是昵称 |
| 5 | CMD_LOGIN_RES | 登录响应 |

几点设计说明：

- `magic` 用来快速识别非法连接。收到数据先比对 4 个字节，不对就断开，把不可信的输入挡在解析逻辑之外
- `version` 为以后改协议留出判断依据，版本对不上直接拒绝，而不是解析出一堆垃圾
- `cmd` 让一条连接上能跑多种消息，服务端按它分流到不同处理函数
- `length` 是 `payload` 的字节数（不含头），接收方先读满 11 字节的头，再读满 `length` 字节的正文，才算收到一条完整消息
- `length` 有上限校验，防止对端谎报长度导致内存分配失败或负数下标

## 分层

```
server.c / client.c     业务层：登录、昵称、广播
       ↓
protocol.c              消息层：打包、解析、命令字
       ↓
net.c                   传输层：建连、可靠收发
```

- `net.c` 只认识 fd 和字节，负责 `tcp_listen` / `tcp_accept` / `tcp_connect`
- `protocol.c` 知道"消息"是什么，负责 `protocol_pack`、`protocol_unpack`、`protocol_send`、`protocol_recv`
- 业务层才认识"用户""昵称""广播"这些概念

依赖方向只有向下，下层不知道上层的存在。

## 编译

```bash
make
```

手动编译：

```bash
gcc -Wall -Wextra -g -o server server.c net.c protocol.c -lpthread
gcc -Wall -Wextra -g -o client client.c net.c protocol.c -lpthread
```

严格模式，把告警当错误：

```bash
make WERROR=-Werror
```

## 运行

终端 1：

```bash
./server
```

终端 2、3、4……各启动一个客户端：

```bash
./client
```

客户端启动后先输入昵称，登录成功后就能发消息，其他人会看到 `[昵称] : 内容`。

## 服务端实现要点

**并发模型**：一连接一线程。每个连接有独立的读循环，按 `cmd` 分发处理。

**连接表**：`client` 结构体数组，每条记录保存 `fd`、`name`、`is_log`，由互斥锁保护。删除连接时做数组紧凑搬移并清零末位。

**广播**：持锁把已登录连接的 fd 拷进本地快照，立刻解锁，然后在锁外逐个发送。锁只保护数据，不保护网络 IO，否则一个慢客户端会让所有线程卡在等锁上。

**登录**：客户端是"先同步等响应，再开读写线程"。服务端在同一个临界区里完成"查重名 + 写昵称"，避免两个客户端同时用同一个名字都通过。

**错误处理**：

- 忽略 SIGPIPE，避免向已断开的连接发送数据时进程被信号杀死
- 所有系统调用检查返回值，失败路径回收 fd 和内存
- EINTR 在 `protocol_read` / `protocol_write` 内部重试
- 收到的每条消息用完即释放

## 已知限制

- `protocol_pack` 用 `strlen` 计算 payload 长度，所以只能传文本；payload 里出现 `0x00` 会被截断
- 一连接一线程，2000 个连接就是 2000 个线程，每个线程默认 8 MB 栈
- 没有心跳机制，拔网线这类假死连接只能等 TCP 自己超时
- 登录阶段没有设置超时，服务端不响应时客户端会一直阻塞
- 客户端在服务端断开后，还需要按一次回车才能真正退出
- 广播是 O(n)，连接数越多单次广播越慢
