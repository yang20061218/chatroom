# Linux 多线程聊天室

用 C 写的 TCP 聊天室。服务端支持多客户端并发连接，任意客户端发出的消息会实时广播给其他所有在线客户端。

这是网络编程学习路线上的第一个项目，代码里保留了从"能跑"到"可靠"的每一步演进。

## 当前功能

- 多客户端并发，一连接一线程
- 消息实时广播
- 客户端上下线通知
- 自定义应用层协议，正确处理 TCP 粘包拆包
- 连接数上限保护，超出时拒绝新连接而不是崩溃

## 协议

自定义了一个最简单的应用层协议，用来在字节流里划出消息边界：

```
+----------+------------------+
|  length  |     payload      |
|  4 字节  |   length 个字节  |
+----------+------------------+
```

- `length` 用**网络字节序**编码，发送时 `htonl`，接收时 `ntohl`
- `payload` 是消息正文，最长 64 KB，超出直接断开连接
- 接收方先读满 4 个字节拿到长度，再读满对应字节数的正文，才算收到一条完整消息

长度上限是必须的：如果对端谎报一个 2 GB 的长度，程序不能真的去 `malloc` 那么多内存，更不能拿着负数当数组下标。

## 编译

```bash
make
```

手动编译：

```bash
gcc -Wall -Wextra -g -o server server.c net.c -lpthread
gcc -Wall -Wextra -g -o client client.c net.c -lpthread
```

严格模式，把告警当错误：

```bash
make WERROR=-Werror
```

## 运行

终端 1：

```bash
./server
```

终端 2、3、4……各启动一个客户端：

```bash
./client
```

在任意客户端输入内容并回车，其他客户端会收到广播。

## 目录结构

```
.
├── server.c        服务端
├── client.c        客户端
├── net.c           套接字工具层：建连、可靠收发、协议编解码
├── net.h
├── Makefile
└── test_sticky.py  粘包测试脚本
```

分层的原则：`net.c` 只认识 fd 和字节，不认识"客户端""消息"这类业务概念；广播逻辑放在 `server.c` 里。依赖方向只有上层依赖下层。

## 服务端实现要点

**并发模型**：一连接一线程。每个连接有独立的读循环，读到一条完整消息后广播给所有人。

**连接表**：全局数组 `clientfds` 加计数 `clientnum`，由互斥锁保护，删除连接时做数组紧凑搬移。

**广播**：持锁把 fd 拷进本地快照，立刻解锁，然后在锁外逐个发送。锁只保护数据，不保护网络 IO，否则一个慢客户端会让所有线程卡在等锁上。

**错误处理**：

- 忽略 SIGPIPE，避免向已断开的连接发送数据时整个进程被信号杀死
- 所有系统调用检查返回值，失败路径回收 fd
- EINTR 在 `net.c` 内部重试，调用方不用管
- 收到的消息用完即释放，避免内存泄漏

## 已知限制

- 协议只有长度字段，没有消息类型。所有人共用一个房间，没有昵称
- 服务端拼显示文本用 1300 字节的固定缓冲区，单条消息超过约 1250 字节会被截断
- 广播是 O(n)，连接数越多单次广播越慢
- 一连接一线程，2000 个连接就是 2000 个线程，每个线程默认 8 MB 栈
- 没有心跳机制，拔网线这类假死连接只能等 TCP 自己超时
- 客户端在服务端断开后，还需要按一次回车才能真正退出
