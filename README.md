# Linux 多线程聊天室

用 C 语言写的 TCP 聊天室。服务端支持多客户端并发连接，任意客户端发出的消息会实时广播给其他所有在线客户端。

这个项目是网络编程学习路线的第一步，代码里刻意保留了从"能用"到"可靠"的每一步演进过程。

## 当前实现

**服务端**

- 一连接一线程的并发模型，每接入一个客户端创建一个线程
- 全局连接表由互斥锁保护，删除连接时做数组紧凑搬移
- 广播时先在锁内拷贝一份 fd 快照，解锁之后再逐个发送，避免慢客户端拖住全局
- 连接数上限保护，超出时拒绝新连接而不是崩溃
- 忽略 SIGPIPE，避免向已断开的连接发送数据时整个进程被信号杀死
- 区分 recv 的正常关闭（返回 0）与错误（返回负值），EINTR 自动重试
- 所有系统调用的返回值都有检查，失败路径有错误输出
- 启动时设置 SO_REUSEADDR，避免重启时端口被占用

**客户端**

- 读线程与写线程分离，共用同一个 socket
- 标准输入结束或发送失败时用 `shutdown(SHUT_WR)` 做半关闭

## 编译

```bash
make
```

或者手动编译：

```bash
gcc -Wall -Wextra -Werror -g -o server server.c -lpthread
gcc -Wall -Wextra -Werror -g -o client client.c -lpthread
```

## 运行

先启动服务端：

```bash
./server
```

再开几个终端，每个终端启动一个客户端：

```bash
./client
```

在任意客户端里输入内容并回车，其他客户端会收到广播。

## 已知限制

这些不是 bug，而是当前阶段有意留下的，后面会逐个解决：

- 一次 recv 当作一条完整消息处理，没有解决 TCP 粘包拆包。长消息会被截断，连续发送的两条消息可能被合并
- 消息里直接内嵌了 `[clientN]` 前缀，没有应用层协议
- 一连接一线程，连接数受线程数限制，1000 个连接就是 1000 个线程
- 没有心跳机制，无法识别假死连接
- 客户端在服务端断开后，需要按一次回车才能真正退出
